# Rules

- Fewest tokens, fewest lines. Less code = fewer bugs, lower overhead, higher performance.
- New code must earn its place. No speculative abstraction, no unused flexibility, no half-finished features.
- Delete code that doesn't carry its weight rather than leaving it as legacy dead weight.
- No docs. Code is truth. Comments only explain non-obvious why, never what.
- Paths not taken belong in commit messages, not comments or dead code.
- Fewer dependencies is better, but don't reinvent a wheel a good dependency already solves fast.
- Prefer lower-level, minimal code — it's faster and has less surface area.
- Tests must be fast and aggressive (try to break the code), never padded or slow for their own sake.
- Reason from formal logic and evidence, not vibes or guesses.
